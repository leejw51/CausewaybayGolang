# CAUSEWAYBAY GO — the web build

The same game as [`../love2d`](../love2d), in a browser. The rules are Rust
compiled to wasm; TypeScript is the shell that gives them a canvas, a keyboard,
Web Audio, somewhere to save and the clipboard.

```bash
make start        # http://localhost:5310
make check        # what CI runs
make deploy       # to Cloudflare Pages
```

## What lives where

```
crates/goset-core/   the rules, compiled to wasm32-unknown-unknown
crates/mkassets/     a build tool: love2d/assets -> public/art
src/engine/          layout, type, art, chrome, input — the browser's half
src/game/            the renderer, the effects, the scenes, the PNG disk
src/audio/chip.ts    the 8-bit effects, synthesized at boot
public/data/         the questions, generated (not committed)
public/art/          the art, generated (not committed)
```

**The core decides what is true; the shell decides what it looks like.** Which
street is open, whether an answer counts, what a combo pays, where "continue"
goes: all Rust, all exercised by `cargo test` with no browser attached. Alex
walking between two dots on the overworld, the screen shake after a wrong
answer, the confetti: all TypeScript, because none of it changes the game.

The two talk in three narrow places, and the shapes of them are the whole
design:

| | |
|---|---|
| `core.view()` | a snapshot of everything on screen, already translated. Rebuilt only when `core.version()` moves, so a still frame costs one integer rather than four kilobytes of JSON. |
| `core.anim()` | five floats — where Alex and the camera are — because those *do* change every frame. |
| `core.events()` | what the rules asked the shell to do: play this blip, throw confetti there, save, copy this to the clipboard. |

An event names a sparkle as a fraction of the scene band rather than a pixel,
because the core does not know how tall that band is. That is the rule the
split follows everywhere: nothing about pixels crosses into wasm, and nothing
about rules crosses out.

## The questions are not copied

`public/data/game.json` is generated by `love2d/tools/dump_web.lua`, which
reads `src/quests.lua`, the twenty `src/data*.lua` chips and `src/i18n.lua`
with plain luajit and encodes them unchanged — a translated field is still the
`{ en, ko, yue }` table the desktop game reads, and the by-English tables of
`src/lang/*.lua` ride along beside it.

So there is one copy of every question, in Lua, and a fix reaches both builds
with one edit. `cargo test` loads that file and plays all 140 streets, so a
blank whose `accept` list no longer contains its own answer fails the web
build's suite too.

The art is generated the same way. `crates/mkassets` does at build time what
`love2d/src/assets.lua` does at every launch — keys the magenta studio backdrop
out, crops each character to its ink, packs it into a 32x48 cell — and writes
the backgrounds as JPEG, which is where nearly all of the 48 MB goes.

## What is different from the desktop build

Not the game. The differences are all places where a browser is not a laptop:

- **Saves.** `localStorage` instead of JSONL in `~/.causewaybaygo`. Only the
  record that would have been the last line is kept, which is all either build
  ever read. The attempt log is gone.
- **Exports.** Markdown, CSV, JSONL, plain text and the PNG disk all download.
  SQLite does not: there is nowhere in a browser to put a database file that a
  person could then open, so that one format stays on the desktop.
- **Fonts.** Press Start 2P and VT323 ship with the page; the CJK fallback is
  whatever the reader's system has, rather than the 12 MB Noto the `.love`
  carries.
- **Fullscreen** is the browser's, and **portrait** (F1) is a layout switch
  rather than a window resize. The layout also *follows* the window until
  somebody presses F1: a phone turned on its side should turn with it, which
  is a thing a desktop window never does.
- **Typing on a phone.** The game is one canvas and a canvas cannot take
  focus, so a soft keyboard would never appear. A tap while a blank is open
  focuses a field nobody can see, and what the keyboard puts in it is read out
  one character at a time — which is also what makes a Korean or Japanese IME
  work, since only the finished text ever lands.

Everything else — the seven languages, AUTO, the two-tier hint, the combo
pitch climbing with the streak, the fourteen badges, the three tiers of CLEAR
effect — is the same game, ported line for line.

## The suites

```bash
make test-rust   # the rules, headless, against the real game.json
make test-web    # type, layout, audio, effects, storage, keys
make e2e         # a real browser plays the game
make e2e-dist    # the same suite against the Cloudflare bundle
```

`make e2e-dist` is the one that earns its keep at deploy time: it serves the
production bundle through Cloudflare's own runtime and checks the things that
only break in the gap between Vite and production — a wasm file served with
the wrong content type (streaming instantiation refuses anything but
`application/wasm`), an asset Vite resolved from source and never copied into
`dist`, a base path that only works under the dev server.

## Deploying

```bash
export CLOUDFLARE_API_TOKEN=...   # needs "Cloudflare Pages: Edit"
make deploy
```

The game is static — a page, a wasm module, a directory of art and one JSON
file of questions — so Pages uploads `dist/` and nothing runs on the server
side. `make deploy-workers` is the same bundle on the Workers Static Assets
route, kept because it is a one-line switch if the account ever moves; it wants
a token with `Workers Scripts: Edit`, which the Pages token does not carry.

## Keys

Same as the desktop game. `1`–`7` jump into a street, `Q` cycles the quests of
a track, `TAB` cycles Go / Rust / Python (and is the hint key inside a street),
`ENTER` submits, `F5` plays the street for you, `F6` opens SHARE, `F1` turns
the layout on its side, `F3` changes language, `F4` mutes, `F11` is fullscreen,
`ESC` goes back.
